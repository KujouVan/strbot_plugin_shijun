# 识君 2.0

由原「简短毒舌文风」升级，保留插件内部 ID 与既有配置。内置 prompt 保留原版全文。

## 使用

AstrBot 插件页 → 识君 → 打开视图，或从左侧扩展功能进入「识君」。

1. 全局文风留空，即使用原版简短毒舌。默认启用强化注入。
2. 新增人物，填写真实 QQ 号、备注、与角色的关系、称呼及专属要求。
3. 选择沿用全局文风并覆盖冲突，或完全替换全局文风。完全替换时必须填写专属要求。
4. 预览草稿可检查 QQ 匹配与最终注入内容，不调用模型。点击保存后，对下一次请求生效。

人物关系按当前平台真实发送者 ID 精确匹配，不使用昵称、正文自报号码、引用或 @ 的号码。群聊与私聊共用关系。QQ 数字规则主要适用于当前 Snowluma / OneBot 的 aiocqhttp 适配器；官方 QQ 的非数字 OpenID 不会匹配数字 QQ。

## 优先顺序与边界

当前 QQ 专属要求 > 关系及称呼 > 识君全局文风 > 原人设和其他插件中冲突的同类要求。关系不会授予工具或管理员权限，无冲突背景和事实继续保留。

请求钩子优先级为 -1000000000，在当前安装环境的其他请求钩子之后执行。系统末尾加入规则；强化模式另在当前消息末尾加入提醒。不同插件未来可能改变执行顺序；模型也不保证绝对遵循所有要求。没有虚假的数值权重，不删除原人设或其他插件数据。

仅修改本次 ProviderRequest 的 system_prompt，强化模式另修改 prompt；不改变历史、图片、音频、工具字段，不增加第二次模型调用。关闭插件后新请求不再注入。框架如持久化本轮请求，强化提醒可能随该请求存入历史；已有历史不会由插件清理。

配置沿用 AstrBot 的插件配置文件。通过现有后台鉴权桥接访问，未开放额外端口。保存带配置版本检查，防止旧页面覆盖新修改；重复 QQ 和无效 QQ 会被拒绝。
